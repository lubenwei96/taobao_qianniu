# 淘项：淘宝店铺运营协作项目设计

## 目标与已知条件

用户与助手从零合作运营淘宝店铺。助手负责选品分析、标题与详情页草稿、SKU 规划、定价测算、运营复盘以及项目工具开发；用户提供真实货源、成本、店铺和经营数据，决定采购、投放与商品发布。

启动预算为 5000 元以上，具体可投入上限尚未提供；品类尚未确定。不得把预算下限当成已授权支出，不得把示例价格、销量或竞争信息当作真实市场数据。

第一个经营目标：北京时间 2026 年 11 月 11 日，单日经营净利润超过 2000 元。2026 年 10 月 8 日到目标日相隔 34 天。该目标是规划和复盘依据，不是收益承诺。

## 选定路线与演进

首版采用运营工作区加 Python 小工具，使用结构化 CSV 数据与 Markdown 文档。相比先做网页看板，这条路线可以更早支持选品、成本核算和商品准备；相比完整自动化平台，减少目前尚未确定的接口和业务假设。

长期路线：首版数据字段与计算模块保持清晰接口；实际运营证明存在高频管理需求时，再增加网页界面。需要店铺接口时单独确认官方接口能力和授权，不以网页抓取或自动控制千牛作为首版前提。

## 首版交付

1. README：协作流程、目录用途、云端操作、Windows 同步步骤和验证命令。
2. 店铺档案：目标、预算范围、货源与品类确认项、运营任务。
3. 选品模板：候选商品、供应商、成本、发货、售后、竞争观察、数据来源与采集日期。空数据保持为空，不构造排名或推荐结论。
4. 商品模板：标题、卖点与依据、详情页结构、SKU 及图片需求。未经确认的素材保留草稿状态，不直接发布。
5. 日报模板：成交、退款、订单成本、推广、其他费用及利润成熟度。
6. Python 定价与目标测算工具：纯标准库，可通过命令行运行；计算模块独立于文件和界面。
7. 自动化测试：覆盖利润公式、目标单量、非法输入、货币精度及盈亏边界。

## 利润口径与计算规则

售价指优惠后实际成交商品金额；采购成本、包装、商家承担的运费、平台费率、每单推广成本、预计每单售后损失分别输入，避免重叠扣减。

预计每单贡献利润 = 实收售价 × (1 − 平台费率) − 采购成本 − 包装成本 − 商家运费 − 每单推广成本 − 预计每单售后损失。

预计日经营净利润 = 每单贡献利润 × 日成交单量 − 日固定及其他经营费用。经营净利润包括用户录入的经营费用；未录入的税费、人工等不能声称已经扣除。

为了严格超过 2000 元，所需单量 = floor((2000 + 日固定及其他经营费用) / 每单贡献利润) + 1。贡献利润非正时明确提示该参数组合无法通过增加单量达到目标；不返回虚构单量。

金额使用 Decimal，展示保留两位小数，目标单量计算使用未提前四舍五入的贡献利润。费用必须非负，费率范围为 0 到 1，拒绝 NaN、Infinity、非数字及非法单量；输入错误返回非零退出码和明确原因。

售价、费率和所有费用都来自用户输入或带来源的调查。示例明确标记为假设。贡献利润 20、40、80 元且日固定费用为零时，分别至少需要 101、51、26 单才能严格超过 2000 元。

实际经营利润按店铺数据复盘；尚未结清的退款、售后和费用计提以“预计”标记，不能以 11 月 11 日 GMV 代替净利润，也不能把单日活动结果外推为稳定日利润。

## 工作流与阶段检查

- 10 月 8–12 日：搭建工作区与工具，确认可投入预算上限、每周投入时间、货源、店铺状态；收集带日期和来源的候选商品信息。
- 10 月 13–19 日：筛选候选、核验样品与供应商、建立成本模型；根据实际结果决定是否进入商品准备。
- 10 月 20–26 日：准备标题、详情页与 SKU 草稿，用户完成商品发布与履约准备；记录真实转化和售后反馈。
- 10 月 27–11 月 3 日：复盘真实单量、每单利润与履约能力，仅在数据支持时扩量。
- 11 月 4–11 日：确认库存、发货与客服容量，按日记录费用和利润，在目标日及售后结算后复盘。

这些日期是规划检查点，不是无条件采购或投放指令。若真实数据不支持目标，更新预测并说明缺口，不制造销量或收益。

## 云端、个人电脑与数据边界

云端使用现有 /workspace/taobao_qianniu 检出。任务已经隔离，无需创建 Git worktree。通过 GitHub 保存代码、模板和可公开的运营文档；电脑上可以检出到 F:\淘项，其他电脑使用各自实际目录。助手无法直接访问用户电脑的 F 盘。

提交前检查仓库可见性与待提交内容。店铺密码、令牌、客户资料、订单明细、真实供应商报价与私人经营账本不进入 Git；本地私人数据放入忽略目录，通过用户选择的私人存储同步，不能承诺 GitHub 同步这些数据。首版不要求店铺凭据，不配置自动采购、自动投放或自动发布。

同步文档说明先拉取再编辑、有本地改动时先保存、发生冲突时人工合并；不使用 reset --hard 或覆盖既有 F:\淘项 内容。提交并推送成功与用户电脑实际同步是两项独立验证。

## 环境与验证

Python 3.11 及以上，无第三方运行依赖。Windows 与 Linux 使用同一计算模块；Windows 同步命令提供 PowerShell 示例，但仅在可用平台上执行并报告结果。

验证包括：真实执行单元测试；命令行正常案例与非零退出的错误案例；严格大于目标的边界案例；提交前工作区检查。没有 web 服务，因此无需常驻进程或端口，也不生成 localhost 预览。

云环境只在有必要初始化步骤时保存 install_script；start_skill 记录工作目录、Python 版本、测试与常用测算命令以及无需 worktree 的说明。保存配置不等于发布，也不等于在新机器验证成功。首次发布由用户在环境设置中完成。

## 验收边界

首版完成的标志是模板与测算工具可用、测试通过、代码已提交且明确报告推送状态、必要云配置已保存。2026 年 11 月 11 日利润目标需要真实经营数据单独验收，不能以软件交付代替经营成功。
